# v0.4.1

这一版解决两类「装上了但用不了」的问题，**画面没有变化**。

---

## ① OBS 里一直显示「加载中」（重要）

**现象**：同一个 `CCTOverlay.html`，双击用 Chrome 打开完全正常，放进 OBS 里就永远停在
「当前状态：加载中」，刷新也没用。

**原因**：OBS 的浏览器源底层是 CEF，加载 `file://` 页面时会**禁掉页面里发出的请求**。
覆盖层拿不到 `:32270`（CCT）和 `:32271`（LevelWatcher）的数据，就只能显示「加载中」。
这不是配置错误，也不是你装错了。

**改法**：别再让 OBS 加载本地文件，改用它自带的 http 地址 —— 页面和接口同源，不受限制。

1. 更新 **LevelWatcher 到 0.4.0**（这一版才开始提供这个地址）
2. OBS 那个源：**取消勾选「本地文件」**，URL 填：

   ```
   http://localhost:32271/overlay/
   ```

3. 在源上点一次「刷新」

> 游戏没开时这个地址打不开，是正常的（由游戏里的 Mod 提供）。
> 建议在源上勾选「**源可见时刷新**」，换场景时自动重新加载。

---

## ② 状态卡现在能说清「是哪一环出了问题」

有人反馈「一直显示加载中」，排查时发现最麻烦的不是 bug 本身，而是**四种完全不同的情况
显示的是同一个词**：

| 实际情况 | 旧版显示 |
| --- | --- |
| 游戏在关卡里 | **加载中** ← 这本身就是 bug |
| LevelWatcher 没响应（`:32271` 连不上） | 加载中 |
| 脚本一行都没跑（文件没拷全 / 路径不对） | 加载中 |
| 脚本抛异常了（版本不匹配） | 加载中 |

现在：

| 状态卡显示 | 含义 | 怎么办 |
| --- | --- | --- |
| **未初始化** | 脚本一行都没跑 | 检查 `ExternalOverlay` 里那 4 个文件是否都在 |
| **脚本错误** | 脚本抛异常了 | 下方提示条会写出**哪个文件 + 什么原因** |
| **LevelWatcher 未响应** | 页面连不上 `localhost:32271` | 确认 LevelWatcher 在 Mod 列表里、浏览器能打开 `http://localhost:32271/` |
| **CCT 未响应** | 连上了，但 `:32270` 拿不到数据 | 查 CCT 是否加载、Everest 调试模式是否开着 |
| **关卡中 / 主页面 / 标题画面 / 菜单** | 一切正常 | — |
| **加载中** | 真的在加载（Loader 场景） | 等一秒 |

> 「在关卡里」以前显示成「加载中」，这是这一版修掉的显示 bug。

## 升级方法

**① 覆盖层**（4 个文件）覆盖到 `Celeste\ConsistencyTracker\external-tools\ExternalOverlay\`：

```
CCTOverlay.html
CCTOverlay.js
CCTOverlay.css
Timing.js
```

或者直接解压 `MapClearingStats-Overlay-v0.4.1.zip` 覆盖整个文件夹。

**② LevelWatcher** 解压 `LevelWatcher.zip` 覆盖到 `Celeste\Mods\LevelWatcher\`
（`everest.yaml` + `bin\LevelWatcher.dll`），然后**重启游戏**。

> 不更新 LevelWatcher 也能用 —— 只是 OBS 那边仍然得用「本地文件」，
> 而那条路在 OBS 里是走不通的。所以用 OBS 的话**必须**更新。

> ⚠️ 覆盖完在 OBS 的源上点一下「刷新页面」（或右键源 → 刷新）。
> 覆盖层不会自己热更新。

## 兼容性

- 配置、存档、历史数据**不受影响**，直接覆盖即可
- 需要 **Chrome / Edge 116+**（置顶悬浮用的是 Document PiP；OBS 浏览器源里这个按钮本来就不显示）
- LevelWatcher **0.4.0**：只多了一个 `/overlay/` 静态文件接口，原有的 `:32271/` JSON 接口不变
