# v0.4.1

**一次排查向的修复**：功能没变，但状态卡现在能**说清是哪一环出了问题**。

---

## 为什么要改

有人反馈「覆盖层一直显示加载中，游戏开不开都一样」。排查时发现最麻烦的地方不是 bug 本身，
而是**四种完全不同的情况显示的是同一个词**：

| 实际情况 | 旧版显示 |
| --- | --- |
| 游戏在关卡里 | **加载中** ← 这本身就是 bug |
| LevelWatcher 没响应（`:32271` 连不上） | 加载中 |
| 脚本一行都没跑（文件没拷全 / 路径不对） | 加载中 |
| 脚本抛异常了（版本不匹配） | 加载中 |

看到「加载中」，根本不知道往哪查。

---

## 现在会显示什么

| 状态卡显示 | 含义 | 怎么办 |
| --- | --- | --- |
| **未初始化** | 脚本一行都没跑 | 检查 `ExternalOverlay` 里那 4 个文件是否都在 |
| **脚本错误** | 脚本抛异常了 | 下方提示条会写出**哪个文件 + 什么原因** |
| **LevelWatcher 未响应** | 页面连不上 `localhost:32271` | 确认 LevelWatcher 在 Mod 列表里、浏览器能打开 `http://localhost:32271/` |
| **关卡中** | 一切正常，人在关卡里 | — |
| **主页面 / 标题画面 / 菜单** | 一切正常 | — |
| **加载中** | 真的在加载（Loader 场景） | 等一秒 |

> 「在关卡里」以前显示成「加载中」，这是这一版修掉的显示 bug。

---

## 还改了

- **脚本出错不再安静**：页面会显示「脚本错误」和具体原因，而不是停在某个状态词上让人猜
- **HTML 占位文字**从「加载中」改成「未初始化」—— 页面白到连脚本都没跑时，不再伪装成「游戏在加载」

---

## 升级方法

覆盖到 `Celeste\ConsistencyTracker\external-tools\ExternalOverlay\`：

```
CCTOverlay.html
CCTOverlay.js
CCTOverlay.css
Timing.js
```

或者直接解压 `MapClearingStats-Overlay-v0.4.1.zip` 覆盖整个文件夹。

> ⚠️ 覆盖后在 OBS 的浏览器源上点一下「刷新页面」（或右键源 → 刷新）。
> 覆盖层不会自己热更新。

---

## 兼容性

- 配置、存档、历史数据**不受影响**，直接覆盖即可
- 需要 **Chrome / Edge 116+**（置顶悬浮用的是 Document PiP；OBS 浏览器源里这个按钮本来就不显示）
- `LevelWatcher` 这一版**没有改动**，不用重装
